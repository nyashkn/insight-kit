Feature platform + claim bundle

Five extensions that turn D · Provenance loop into a complete authoring surface: a feature catalog agents browse instead of reinventing groupbys; claim bundles that pin narrative + chart + data under one fingerprint; Altair → Evidence bridge for vision-critic-friendly charts; cross-claim links as first-class DAG edges; staleness deltas auto-appended when sources refresh via h_dlt.

arc features (DAG nodes) → claim bundles → chart specs (Altair) → linked claims → staleness deltas

§0Why this — agent ergonomics over inline math

Today the analyst agent invents the same aggregations every run. gmv_monthly_by_channel gets rewritten in five notebooks; MER formula re-derived from scratch. Hallucination class: "agent wrote sum but meant mean" — caught only by reviewer. Same problem on the rendering side: Rill's metrics/*.yaml at dockblocks-ops/rill_project/ already decoupled measures from dimensions for live dashboards. The .md narrative surface doesn't have that decoupling — every paragraph re-invents the metric definition implicitly.

The fix: features = named Hamilton nodes with tags. Analyst agent's tool surface becomes list_features(grain="month", measure="mer") not "write a groupby." The data_eng agent owns the feature library; analyst consumes. Inline math forbidden — must request a named feature via data_eng PR.

§1Feature catalog — DAGWorks pattern applied

Source: DAGWorks "Building a better feature platform" + apache/hamilton/examples/feature_engineering. Core idea: functions = features = lineage = serving. One codebase, three lifecycles (offline analyst run, online dashboard render, eval/critic).

Naming convention

Function name encodes measure_aggregation_grain_dimension. Hard rule: data_eng agent rejects PRs that don't conform. Convention kills the "mer vs MER vs marketing_efficiency_ratio" hallucination at PR review.

# features/marketing.py
from hamilton.function_modifiers import tag, check_output

@tag(stage="agg", grain="month", measure="gmv", role="measure")
@check_output(schema=GMVMonthlySchema)
def gmv_kes_sum_monthly_by_channel(
    orders_clean: pd.DataFrame,
) -> pd.DataFrame:
    """GMV in KES, summed per (channel, month). Grain = month."""
    return (orders_clean
        .groupby(["channel", pd.Grouper(key="order_dt", freq="MS")])
        ["gmv_kes"].sum().reset_index())

@tag(stage="agg", grain="month", measure="ad_spend", role="measure")
@check_output(schema=AdSpendMonthlySchema)
def ad_spend_kes_sum_monthly_by_channel(
    meta_ads_clean: pd.DataFrame, google_ads_clean: pd.DataFrame,
) -> pd.DataFrame: ...

@tag(stage="derived", grain="month", measure="mer", role="measure")
@check_output(schema=MERMonthlySchema)
def mer_monthly_by_channel(
    gmv_kes_sum_monthly_by_channel: pd.DataFrame,
    ad_spend_kes_sum_monthly_by_channel: pd.DataFrame,
) -> pd.DataFrame:
    """Marketing Efficiency Ratio = GMV / ad spend. One node = one definition."""
    merged = gmv_kes_sum_monthly_by_channel.merge(
        ad_spend_kes_sum_monthly_by_channel, on=["channel", "order_dt"])
    merged["mer"] = merged["gmv_kes"] / merged["ad_spend_kes"]
    return merged

§2Claim bundle — narrative + chart + data joint-fingerprinted

Today: .md narrative drifts from claim.jsonl data drifts from chart spec. Three independent surfaces, three drift sources, one rendered page that lies. Fix: package them under one claim_id.

Layout

claims/
└── MD-D-005/
    ├── claim.json              # typed fields, lineage, fingerprints
    ├── narrative.md            # local prose interpretation (this claim only)
    ├── chart.vl.json           # Vega-Lite spec (from Altair, §3)
    ├── chart.png               # rasterized for vision-critic
    ├── data_snapshot.parquet   # exact rows used — frozen at build
    └── fingerprints.json       # {data: sha, prose: sha, chart: sha}

Three fingerprints, three invalidation paths

Independent. Edit prose → critic re-reads prose alone. Underlying source refreshes → data fingerprint diverges, chart re-renders, prose stays valid until prose-vs-data drift detected (§5).

Authoring sample — annotation as claim reference

The killer pattern. Annotations stop being hand-typed strings. They become claim refs that auto-update.

# claims/build_mer_trend.py — Hamilton node
import altair as alt

@tag(claim_id="MD-D-009", tier="D", audience="founder")
@check_output(schema=ClaimChartSchema)
def claim_md_d_009_chart(
    mer_monthly_by_channel: pd.DataFrame,
    prior_intervention: Claim,  # injected via Hamilton, see §4
) -> ChartSpec:
    base = (alt.Chart(mer_monthly_by_channel)
        .mark_line()
        .encode(x="order_dt:T", y="mer:Q", color="channel:N"))

    intervention_rule = (alt.Chart(pd.DataFrame({
            "x": [prior_intervention.fields["intervention_date"].value]}))
        .mark_rule(strokeDash=[4,3], color="#C97B7B")
        .encode(x="x:T"))

    callout = (alt.Chart(pd.DataFrame({
            "x": [prior_intervention.fields["intervention_date"].value],
            "y": [2.5],
            "label": [prior_intervention.statement]}))
        .mark_text(align="left", dx=6, fontSize=11)
        .encode(x="x:T", y="y:Q", text="label:N"))

    spec = (base + intervention_rule + callout).to_dict()
    return ChartSpec(
        claim_id="MD-D-009",
        spec=spec,
        references=[prior_intervention.claim_id],  # lineage edge
        fingerprint=hash_spec(spec))

    # Playwright headless against `npm run dev` localhost

§5Staleness — h_dlt fingerprints + auto-delta on claim

Three-part design: data fingerprint stored on claim (§2) · staleness watcher detects diverge · delta computed and appended to claim bundle · Evidence renders staleness badge.

Watcher job

# jobs/staleness_watch.py — runs hourly via cron
@tag(role="watcher")
def detect_stale_claims(
    claims_registry: ClaimRegistry,
    dlt_state: DltState,  # reads .dlt/pipeline_state.json
) -> list[StalenessReport]:
    current = dlt_state.source_fingerprints()
    # {"shopify.orders": "2026-05-14T09:00/sha256:def...",
    #  "meta.ads":       "2026-05-14T09:00/sha256:abc..."}
    stale = []
    for claim in claims_registry.claims:
        for src, old_hash in claim.data_fingerprint.items():
            if current.get(src) != old_hash:
                stale.append(StalenessReport(
                    claim_id=claim.claim_id,
                    source=src,
                    old_hash=old_hash, new_hash=current[src],
                    detected_at=now()))
    return stale

Delta computation + bundle append

def compute_and_append_delta(report: StalenessReport) -> None:
    claim_old = load_claim_bundle(report.claim_id)
    claim_new = driver.execute([f"claim_{report.claim_id.lower()}"])[0]
    delta = ClaimDelta(
        detected_at=report.detected_at,
        source_changed=report.source,
        field_deltas={
            name: FieldDelta(
                was=claim_old.fields[name].value,
                now=claim_new.fields[name].value,
                pct=(new.value - old.value) / old.value
                    if old.value else None)
            for name, (old, new) in zip_fields(claim_old, claim_new)
            if old.value != new.value
        },
        policy=audience_policy(claim_old.audience))
    # write claims/{id}/staleness.json — bundle gains a 6th file
    write_bundle_file(report.claim_id, "staleness.json", delta.json())

h_dlt as fingerprint source · free infra
dlt already maintains .dlt/pipeline_state.json with per-source-per-partition cursors and incremental hashes. Hamilton node dlt_state.source_fingerprints() reads this directly. Zero extra storage. The same h_polars / h_narwhals plumbing covered in C·DF stack carries through — no new dependencies.

Glossary

Provenance loop
Earlier page (D): six-layer mechanism — claim schema, <ClaimNum>, <ClaimChart>, L6 preflight, post-render diff, inline critiques.
Feature catalog
Named Hamilton nodes tagged with measure/grain/role. Analyst browses; data_eng owns. Replaces inline groupbys.
Claim bundle
Filesystem dir claims/{id}/ holding claim.json + narrative.md + chart.vl.json + chart.png + data_snapshot.parquet + fingerprints.json. Joint-fingerprinted across three axes.
Altair → Evidence
Python authors charts as Altair; Hamilton emits Vega-Lite spec JSON; Evidence renders via <VegaLite> wrapper. Spec also rendered to PNG for vision-critic.
Linked claims
Claim inputs declared as Hamilton DAG edges via parameterize_from_claim. Free lineage, fingerprint propagation, cycle detection.
Staleness delta
Auto-computed delta between snapshot fields (at publication) and current rebuild. Written to staleness.json in bundle. Triggers badge or block depending on audience policy.
h_dlt
Hamilton wrapper around dlt. Per-source partition cursors + content hashes maintained in .dlt/pipeline_state.json. Source of truth for data fingerprints.
MER
Marketing Efficiency Ratio = GMV / ad spend. Sign-bearing on month boundaries when ad spend partial; partial-month MER was the source of the 9.26x bug.
Rill
OSS dashboard tool at dockblocks-ops/rill_project/. YAML measures × dimensions × dashboard. Insight-kit feature catalog mirrors this in Python.
vl-convert
Headless Vega-Lite renderer (Rust binding). Converts spec JSON → PNG without a browser. Used by critic to produce vision-checkable images.
