Worked example Dock Blocks · repeat-customer value + Charleston risk

Q: “Are repeat customers worth more, and is Charleston concentration a risk?” Two claims, one cited benchmark. Watch DOCK-D-128 go from a bare draft to a published, content-addressed record — and what the gate adds.

1 · researcher snapshots an external benchmark → DOCK-X-007

ref_x = ik_research_emit(
  "DOCK-X-007", "hbr.org/repeat-ltv", query="repeat customer LTV multiple retail",
  source="hbr", snapshot={"finding": "repeat buyers 2-3x first-order value", "n": 12},
  timestamp="2026-06-08T09:00:00+00:00", run_state=state, run_dir=run_dir,
)  # → records/DOCK-X-007/snapshot.json (immutable) + snapshot_fingerprint injected

2 · analyst emits the claim — draft first, then published

# draft: no input_data → data_fingerprint_source = "payload" (self-derived, V22)
ref = ik_claim_emit(
  "DOCK-D-128", {"repeat_value_multiple": (2.3, "x")},
  cites=["DOCK-X-007"], run_state=state, run_dir=run_dir,
)
# promote to published: real input_data registered + coverage warning for thin n
ref2 = ik_claim_emit(
  "DOCK-D-128b", {"repeat_value_multiple": (2.3, "x")},
  tier="published", audience="board", cites=["DOCK-X-007"],
  supersedes="DOCK-D-128",                       # correction = new record (V3)
  input_data=cohort_parquet_bytes,               # → source = "registered_input"
  coverage={"n": 412}, selection={"date_window": "2025Q4", "baseline": "first_order"},
  run_state=state, run_dir=run_dir,
)

The critic answer, plainly (your Q3): the critic can critique a chain only by convention — it reads claims.jsonl and names input_claims itself. The gate enforces no cross-record traversal, and apply_critique persists nothing but a counter. So “critiques persisted + connected” is a build target, not shipped. Same for the API-coverage critique in tab 4.
What’s next: an opus readiness-brief (docs/e2e-explainer/readiness-brief.md) sequences these gaps into buildable §T tasks and 1–2 workflows — wiring the dead validation guards first (cheapest real win), then critique persistence + the cites/edge graph that unlocks both chain-critique and the API-coverage check.
