Modules map platform/gate · libs/provenance · .pi · .agents

Four cooperating surfaces. The L1 gate (pure Python lib — zero Hamilton, zero pi) is the only writer of records. The L3 .pi extension (TypeScript) calls it across a uv run subprocess seam. libs/provenance holds the kept kit-root discovery. .agents are the eight role-agents that drive it.

Call-flow .pi → uv run → insight_kit.platform.gate.cli

The L3 TypeScript extension never writes records itself. It marshals a JSON payload, blocks if the run context is missing, then shells out to the Python gate via uv run (C4 lang seam). One fresh process per emit, 60s timeout.

Seam resolves: .pi/lib/core.ts:48 gateArgv → cli.py:251 main → cli.py:120 run_emit → emit.py:432 _record_emit.

The BLOCK-if-RUN_DIR-unset hook (verbatim)

// .pi/extensions/insight-kit.ts:66
pi.on("tool_call", (event) => {
  if (isGateTool(event.toolName) && !process.env.INSIGHT_KIT_RUN_DIR) {
    return {
      block: true,
      reason: `${event.toolName}: INSIGHT_KIT_RUN_DIR is not set. The L1 gate has` +
        " no run directory to write the record into — set it before emitting.",
    };
  }
});

Belt-and-braces: TS blocks the call before spawning uv, and Python independently raises if the dir is still unresolved — store.py:31 resolve_run_dir() priority is --run-dir → INSIGHT_KIT_RUN_DIR → ValueError. No run context ⇒ no record, on both sides of the seam.

Critic reject → re-derive loop REAL enforcement, proven by tests

The old docs described a critic loop. This one is enforced in code: an open high-severity critique on a published/board record raises CritiqueGateError, the correction enters as a new superseding record (immutability, V3), and a named test proves it.

Walk: claim DOCK-D-128 → refute → gate → supersede → re-gate

1

analyst emits DOCK-D-128 as published

“Repeat customers are worth 2.3× first-timers.” Through emit.py:602 ik_claim_emit → record.json written immutably.

2

critic refutes with severity: high

Re-runs the SQL, finds the cohort window double-counts. Emits an open CritiqueState (runstate.py:93) against the published claim.

3

apply_critique gate fires

runstate.py:139 increments critiqueRounds (line 166), confirms record_type ∈ {claim,intervention} (line 169), status==open (line 173), _is_gated_tier true for published/board (line 177 → 132/134), severity ≥ high (line 181) — then raises runstate.py:118 CritiqueGateError. Caller MUST force tier → draft (V16).

4

correction enters as DOCK-D-128b — a NEW record

No mutation (V3). The fixed claim emits with supersedes=DOCK-D-128. The gate verifies the target exists first: emit.py:109 _check_supersedes_exists — missing target raises LayerAValidationError("supersedes-not-found") (emit.py:117). Field defined schema.py:125.

5

re-gate; cap at 3 rounds then auto-downgrade

DOCK-D-128b re-runs the full gate. If critique rounds reach 3, apply_critique stops raising and returns {downgraded:true, tier:"draft"} (runstate.py:189) — the loop never stalls forever.

Diff: old approach vs the gate flat jsonl → content-addressed immutable

Two contrasts. (a) the pre-T25 in-repo legacy (provenance/run.py + claim.py, recovered from git history). (b) the sibling example-shop growth_insights/.eval-out/run/claims.jsonl — flat one-line-per-claim.

OLD — flat jsonl, mutable

Pre-T25 provenance/run.py (1070 lines) + claim.py (103 lines). Last present at e21c665, deleted in df671b2 (T25 cutover).

  • Claims accumulate in-memory self._claims, flushed all at once to one claims.jsonl at Run.__exit__.
  • “Append-only” by comment, not by structure — the whole file is rewritten on exit.
  • No content-addressing — no record_fingerprint; claim_id is caller-supplied / sequential.
  • Validation batched at exit (Layer-B global uniqueness), not per-record at write.
  • Supersedes is a plain field; existence not checked at emit.

NEW — content-addressed, immutable

Post-T25 platform/gate/. Every record validated → fingerprinted → written once → indexed.

  • Content-addressing: record_id derived from sha256 of canonical record.json — fingerprint.py:77 / fingerprint.py:103.
  • Immutability: write-once; re-emit raises FileExistsError (V3) — store.py:65 / refusal store.py:79.
  • Supersedes is checked: target must exist or supersedes-not-found raises — emit.py:109.
  • Per-record validation at the gate, zero partial write on reject (V2) — emit.py:432.
  • L5/L6 audit: rendered numbers must join to a claim field; prose carries zero bare numerics — audit.py:152 / audit.py:242.
  • Provenance honesty: data_fingerprint_source ∈ {registered_input, payload}; published with payload-only → reject (V22) — schema.py:20.
