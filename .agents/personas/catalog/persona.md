# Catalog Persona

## 1. Domain Definition

### In Scope
- Product catalog composition: SKU count, category distribution, fulfillment source split (local vs. DSers/dropship)
- Out-of-stock (OOS) rate estimation and spend-weighted leak sizing
- DPA feed configuration audit: product set filter criteria, availability flags, product_count, orphaned creatives
- Dead set detection: product sets with product_count = 0 still referenced in campaigns
- Fulfillment risk classification: DSers/AliExpress lag exposure vs. locally stocked items
- Product-level ROAS contribution when creative × product set linkage is available
- Price integrity: products listed at cost > typical order AOV (price anomalies)
- Catalog structure interventions: filter rule changes, set retirement, creative reassignment

### Out of Scope
- Paid media budget allocation and demographic ROAS — defer to `ad-spend`
- Customer repeat purchase driven by catalog quality — defer to `retention` for behavioral signal
- Top-of-funnel traffic to product pages — defer to `acquisition`
- Checkout funnel drop-off after product view — defer to `funnel`

### Boundary Notes
- OOS rate for DSers/Aliexpress-sourced SKUs is estimated from industry benchmarks (15–25%) unless a Shopify `inventory_quantity` query is available. All OOS-based leak estimates must be tagged with data source type.
- "Catalog leak" in this domain refers specifically to ad spend reaching SKU slots that cannot convert — due to OOS, price anomaly, or fulfillment failure — not to price erosion or margin compression.
- The `catalog_leak_v2__leak_components.parquet` is the canonical source for this domain. It is generated by the `catalog_leak_v2` worker run.

## 2. Glossary

| Term | Definition |
|------|------------|
| **Catalog leak** | Ad spend directed at catalog SKU slots that cannot produce a completed order. Three causes: (1) SKU is OOS, (2) SKU has fulfillment lag that triggers refund, (3) SKU price is anomalous (too high or too low for category). |
| **OOS drain** | The fraction of DPA spend where the served SKU has `availability != in_stock` at impression time. Estimated: `DPA_spend × estimated_OOS_rate`. |
| **DSers SKU** | A product in the Meta catalog sourced from AliExpress/Aliexpress via DSers integration. Identified by membership in the "Shipped From Abroad" product set. Fulfillment lag: 7–21 days to end customer. |
| **Local SKU** | A product in the "Local Feed" product set (~6,000 SKUs in the demo data). Locally stocked; standard local delivery expectation. |
| **Product set** | A Meta catalog filter configuration that controls which SKUs are eligible for a DPA creative. Key fields: `product_count`, `filter_criteria_summary`. `(no filter)` = all ~100,000 SKUs eligible. |
| **Dead set** | A product set with `product_count = 0`. SKUs have been de-listed but the set was not retired. Referencing a dead set in a new creative results in zero impressions. |
| **Orphaned creative** | A DPA creative whose `product_set_id` does not match any row in the product_sets table. Creative may serve with undefined catalog scope. |
| **Fulfillment lag** | Calendar days from Meta DPA purchase to product delivery to customer. DSers: 7–21 days. Local: 1–3 days. Refund risk rises sharply when lag > customer delivery expectation. |
| **DSers refund lag** | Time from ad spend to refund realization for a DSers order: 21–35 days (order → DSers sync → AliExpress → customer complaint at day 5–7 → refund processed). This is the blind window for spend-to-loss attribution. |
| **Inventory sync cadence** | Frequency at which Shopify inventory state is propagated to the Meta catalog availability flag. Without a webhook, Meta catalog TTL is 24h — meaning a SKU going OOS can continue to receive DPA impressions for up to 24 hours. |
| **Filter criteria** | Meta product set rule applied to the catalog to limit eligible SKUs. `availability = in_stock` is the canonical filter that prevents OOS drain. `(no filter)` or `OR`-type filter without availability check = OOS drain risk. |
| **Leak component** | A row in `catalog_leak_v2__leak_components.parquet` representing a specific leak source with estimated weekly spend and confidence level. |

## 3. Common Claim Patterns

### Pattern 1: oos-drain
- **Shape:** `Product set "<name>" contains <N> SKUs with <filter_type> filter. Estimated OOS rate <X>%. DPA spend at risk: <KES>/week (<KES>/month).`
- **Example:** "Product set 'All Products' (~100,000 SKUs, no filter). Estimated OOS rate 15%. DPA spend at risk: ~125 USD/week."
- **Confidence floor:** medium — OOS rate is estimated; high if Shopify inventory_quantity query confirms

### Pattern 2: dead-set-trap
- **Shape:** `Product set "<name>" (<set_id>) has product_count = 0. <N> creatives reference this set. Risk: new campaigns built on this set serve zero impressions.`
- **Example:** "Flash Sale set (set_id 3000000000000001): product_count = 0, 18 products de-listed. No active creatives today but set persists as future campaign trap."
- **Confidence floor:** high — product_count = 0 is directly observable

### Pattern 3: fulfillment-lag-risk
- **Shape:** `<N> ACTIVE creatives serve "<set_name>" (DSers-sourced, <M> SKUs). Fulfillment lag 7–21d. Refund realization window: 21–35d. Spend at risk this week not confirmed until <date>.`
- **Example:** "5 ACTIVE creatives serve 'Shipped From Abroad' (~56,000 SKUs). Spend this week creates refund risk visible no earlier than ~3 weeks out."
- **Confidence floor:** medium — fulfillment lag estimate from DSers documentation; actual refund rate requires Shopify order data

### Pattern 4: catalog-intervention-lever
- **Shape:** `Applying <filter_rule> to "<set_name>" removes <N> ineligible SKUs. Estimated spend recovery: <KES>/month. Implementation: <steps>.`
- **Example:** "Applying `availability = in_stock` to 'All Products' set removes ~15,000 OOS SKUs. Estimated recovery: 300–530 USD/month redirected to in-stock impressions."
- **Confidence floor:** medium — recovery estimate depends on OOS rate assumption

## 4. Source Data Dependencies

### Bronze (raw ingest)

|-----------------|-------------|-------|
| `catalog_leak_v2__leak_components.parquet` | `leak_source`, `spend_weekly_usd`, `confidence`, `action`, `loop_archetype` | Canonical leak source. Generated by `catalog_leak_v2` worker. |
| `meta_metadata__product_sets.parquet` | `id`, `name`, `product_count`, `filter_criteria_summary`, `filter_raw_json` | Product set quality audit. "All Products" id: 3000000000000000. "Shipped From Abroad": ~56,000 SKUs. |

| `shopify_products_bulk__products.parquet` | `productId`, `title`, `vendor`, `productType`, `status`, `publishedAt` | Product catalog — for category and vendor analysis. |
| `shopify_products_bulk__variants.parquet` | `productId`, `variantId`, `price`, `inventoryQuantity`, `inventoryPolicy` | Inventory quantity and price per variant. OOS = `inventoryQuantity <= 0 AND inventoryPolicy != 'continue'`. |
| `meta_metadata__placement_insights.parquet` | `publisher_platform`, `spend_kes`, `purchases`, `purchase_value_kes`, `roas` | For DPA ROAS by placement — cross-reference with catalog quality changes. |

### Silver / Views
| View | Derivation | Notes |
|------|------------|-------|
| Ad-hoc product set audit query | Join `creatives` on `product_set_id` to `product_sets`; flag orphaned creative_ids | Must be re-run when new creative or set is added |

### Coverage Gaps
- `inventoryQuantity` from Shopify variants is a point-in-time snapshot — OOS rate at any historical date requires a time-series, which is not available in bulk export
- No direct mapping from Meta catalog SKU to Shopify productId in the current extract (linkage via product title or handle is approximate)
- DSers refund rate is not available in any current data source — fulfillment risk is estimated, not observed
- Product-level ROAS from DPA is not exposed in the placement_insights table (aggregated by placement, not by SKU served)

## 5. Standard Analyses

### Analysis 1: Product Set Audit (OOS and Filter Quality)
- **Goal:** Identify product sets serving DPA traffic that lack OOS filtering, quantify spend exposure
- **Inputs:** `meta_metadata__product_sets.parquet` columns `id`, `name`, `product_count`, `filter_criteria_summary`; `meta_metadata__creatives.parquet` for creative-set linkage; `meta_metadata__placement_insights.parquet` for spend
- **Method:** Join creatives to product sets on `product_set_id`. For each active creative, retrieve its set's `filter_criteria_summary`. Flag sets with `(no filter)` or no `availability = in_stock` rule. Estimate OOS spend = set_spend × estimated_OOS_rate (15% conservative, 25% aggressive). Flag dead sets (product_count = 0) and orphaned creatives.
- **Output claim shape:** oos-drain (Pattern 1), dead-set-trap (Pattern 2)

### Analysis 2: Fulfillment Lag Risk Sizing
- **Goal:** Quantify current spend creating delayed refund exposure from DSers-sourced creatives
- **Inputs:** `meta_metadata__creatives.parquet` filtered to `status = ACTIVE`; `meta_metadata__product_sets.parquet` identifying "Shipped From Abroad" set
- **Method:** List all active creatives referencing DSers product sets. Compute their share of recent spend (from placement_insights). Apply 21–35 day refund window to state when current week's spend creates refund risk. Size the exposure in KES.
- **Output claim shape:** fulfillment-lag-risk (Pattern 3)

### Analysis 3: Catalog Composition Analysis
- **Goal:** Measure the split between DSers-sourced and locally-stocked SKUs and assess concentration risk
- **Inputs:** `shopify_products_bulk__products.parquet`, `meta_metadata__product_sets.parquet`
- **Method:** Count SKUs in "Shipped From Abroad" vs. "Local Feed" sets as a % of total "All Products" count. Flag if DSers SKUs > 50% of catalog (systemic fulfillment risk threshold). Analyze product category distribution within each fulfillment type.
- **Output claim shape:** oos-drain with fulfillment source breakdown

### Analysis 4: Inventory Sync Gap Assessment
- **Goal:** Determine the maximum time window in which an OOS SKU can continue to receive DPA impressions
- **Inputs:** `shopify_products_bulk__variants.parquet` columns `inventoryQuantity`, `inventoryPolicy`; knowledge of Meta catalog feed TTL (24h default)
- **Method:** Query current OOS variants (inventoryQuantity <= 0 AND inventoryPolicy != 'continue'). Compute count and % of total SKUs. State that without a real-time webhook, these SKUs remain eligible for DPA impressions for up to 24h after going OOS.
- **Output claim shape:** catalog-intervention-lever (Pattern 4) with sync gap framing

### Analysis 5: Creative-to-Set Orphan Detection
- **Goal:** Find DPA creatives whose product_set_id references a non-existent or retired set
- **Inputs:** `meta_metadata__creatives.parquet` columns `id`, `product_set_id`, `status`; `meta_metadata__product_sets.parquet` column `id`
- **Method:** LEFT JOIN creatives to product_sets on `product_set_id`. Rows with no matching set = orphaned. For active orphaned creatives, flag as undefined catalog scope — impression behavior unpredictable.
- **Output claim shape:** dead-set-trap (Pattern 2) variant for orphaned creatives

## 6. Anti-Patterns

### AP-1: Treating OOS rate as confirmed without Shopify inventory query
**Problem:** Stating "15,000 SKUs are currently OOS" when the OOS estimate is derived from an industry benchmark (15–25% for AliExpress dropship) applied to the ~100,000-SKU catalog count. Without a Shopify `inventory_quantity <= 0` query, the specific OOS count is modeled, not observed.
**Why it happens:** The ~100,000-SKU count is observable; multiplying by a benchmark rate produces a plausible-looking specific number.
**Correct approach:** Distinguish between the modeled estimate ("est. 15,000–25,000 OOS SKUs, confidence medium") and a confirmed inventory query result. Always tag with the data source type.

### AP-2: Claiming catalog fix will recover the full estimated OOS spend
**Problem:** "Adding `availability = in_stock` filter will recover 125 USD/week in wasted spend." In reality, the recovered impressions will be redistributed to in-stock SKUs — some of which may also be low-conversion (wrong category, price mismatch). The intervention reduces OOS waste but the recovered spend does not automatically convert at the account ROAS.
**Why it happens:** The intervention is framed as spend recovery, but it is actually spend redirection with an uncertain conversion uplift.
**Correct approach:** Frame as "redirects ~125 USD/week from OOS impressions to in-stock SKUs. Revenue uplift depends on in-stock SKU conversion rate, which is not independently known."

### AP-3: Assuming a dead product set cannot affect running campaigns
**Problem:** "The Flash Sale set has product_count = 0 — it's harmless because no creatives reference it." While true for existing campaigns, the dead set remains visible in the Meta Ads Manager UI and will be selected by future campaign builders who see the name "Flash Sale" and assume it has products.
**Why it happens:** Analysts focus on current active creative linkages and ignore forward risk from stale sets.
**Correct approach:** Recommend deletion or archiving of any set with product_count = 0, regardless of current creative reference count. Document the set history in a comment before deletion.

### AP-4: Using the 21-35 day DSers refund window as a fixed refund rate
**Problem:** Treating the refund window as if it implies a specific refund rate (e.g., "21-35 day delay means X% of orders will refund"). The window describes timing, not probability. Refund rate depends on supplier reliability, customer service handling, and product category — all unknown without Shopify refund data.
**Why it happens:** The delay estimate is specific and confident-sounding; it invites extrapolation to a rate.
**Correct approach:** State refund window as a timing risk (blind window for attribution), not as a refund rate claim. Refund rate requires Shopify order + refund data, which is a separate analysis.

## 7. Council Escalation Cues

| Trigger Condition | Call | Why |
|-------------------|------|-----|
| OOS rate estimate is load-bearing for a budget pause recommendation | **feynman** | Mechanism verification — confirm the industry benchmark applies to this specific supplier mix before acting on it |
| DSers SKUs exceed 60% of total catalog and DPA campaigns are scaling | **meadows** | Loop 3 (DSers amplifier) archetype — scaling DPA spend increases refund volume in a reinforcing degradation loop |
| Applying `availability = in_stock` filter would reduce product_count by > 30% | **aristotle** | MECE check — confirm the remaining in-stock set is broad enough to sustain DPA retargeting and prospecting separately |
| Product set filter configuration is ambiguous (`OR`-type without named availability rule) | **socrates** | Definitional ambiguity — `OR` filter may include OOS SKUs depending on rule ordering; need to parse `filter_raw_json` |
| Orphaned creative is ACTIVE with material spend | **kahneman** | Alert bias — active creative with undefined catalog scope may be serving impressions on an arbitrary product subset; do not assume it's harmless because it's producing ROAS |
| Catalog fix is recommended alongside a spend scale-up | **meadows** | Fixes-that-fail trap — improving catalog quality may increase ROAS, which triggers spend increase, which may re-saturate Instagram or exhaust local inventory |

## 8. Critic Stress-Tests

### ST-1: OOS rate source challenge
**Probe:** "The analysis states 15,000–25,000 SKUs are OOS. What is the source of the 15–25% OOS rate? Is this from a Shopify inventory query or an industry benchmark?"
**Expected weak point:** The OOS estimate is almost always benchmark-derived unless a live inventory query was run. The specific number range makes it sound observed.
**Pass condition:** Analyst states the source type explicitly. If benchmark: "Industry benchmark for Aliexpress dropship; confidence medium. Shopify `inventoryQuantity` query would promote to high confidence." If Shopify query: show the query result.

### ST-2: Intervention revenue recovery scope
**Probe:** "The filter intervention is estimated to recover 300–530 USD/month. This assumes the recovered impressions convert at account-average ROAS. What is the basis for that assumption?"
**Expected weak point:** The recovery estimate conflates "spend no longer wasted on OOS" with "spend that will generate revenue at the current ROAS." The in-stock SKUs receiving the redirected impressions may have lower conversion rates.
**Pass condition:** Analyst reframes the estimate as "spend redirected from OOS to in-stock impressions" and applies a range of conversion outcomes (best case: account ROAS; realistic: discounted ROAS for the category mix of in-stock SKUs).

### ST-3: Dead set forward risk
**Probe:** "The Flash Sale set has product_count = 0. It has no active creatives today. Why is this flagged as an action item rather than a passive observation?"
**Expected weak point:** If the analyst treats the dead set as harmless because no current creatives reference it, they miss the forward risk of future campaign builders accidentally selecting it.
**Pass condition:** Analyst explains the trap-for-future-builders risk and recommends archival or deletion, not just monitoring.

### ST-4: DSers refund window actionability
**Probe:** "The recommendation is to pause 5 DSers creatives immediately due to 21–35 day refund risk. What is the current estimated exposure — how much of the trailing 3 weeks' DSers spend has not yet been confirmed lost?"
**Expected weak point:** The blind window implies that pausing today stops new exposure but does not eliminate the pending refund wave from prior 3 weeks of spend.
**Pass condition:** Analyst computes trailing 21-day DSers spend as the pending refund exposure. States that pausing eliminates new risk but does not reverse existing exposure. Does not frame the pause as resolving current losses.
