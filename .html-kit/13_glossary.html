Glossary

Adapter hamilton
Object passed to Driver.Builder().with_adapters(...) that implements one or more lifecycle-hook interfaces. InsightKitHook is one such adapter.
Agent insight-kit
A logical role declared in agents.yaml (e.g. analyst-funnel, critic-data-quality, data-eng-bronze). Each agent declares its allowed claim tiers and the council persona it invokes.
Annotation insight-kit
Post-hoc meta-claim emitted by Kahneman or Socrates personas on an existing claim. Stored in annotations.jsonl. Signals: independence, confidence-justified, edge-supported, anchoring, batch_bias_assessment.
HamiltonCacheAdapter hamilton
Lifecycle hook that stores/retrieves node results in a result store keyed by a content-fingerprint. Behaviours: DEFAULT, RECOMPUTE, DISABLE, IGNORE.
Caveat insight-kit
Required text attached to externally-sourced inputs (e.g. Tavily web search, scraped pages). Layer-A rule rejects external ingest with empty caveats.
@check_output hamilton
Decorator that runs validators on a node's result after execution. Built-in validators: range, type, pandera schema. importance="error" raises; "warning" logs.
Claim insight-kit
The atomic provenance object insight-kit emits. Fields: claim_id, tier, statement, value, confidence, caveats, input_claims, supports, refutes, supersedes, evidence_ref, emitter.
Claim ID insight-kit
Namespaced identifier matching ^[A-Z]{2,5}-(D|R|C|I|V|X|ETL_[RCM])-\d{3,}$. Example: DOCK-D-001, NMK-BA-002.
claims_registry.yaml insight-kit
Per-project mapping of claim-ID prefixes to label, tier, emitter role, and description. Example: BA → brevo-attribution / derived / council-attribution.
Claim Tier insight-kit
Enum: raw, derived, critic, initiative, viz, counterfactual, etl_raw, etl_clean, etl_metric.
@config.when hamilton
Conditionally include or exclude a node based on Driver config. The cleanest way to toggle notebook-vs-prod paths without code duplication.
Council persona insight-kit
A named reasoning style (meadows, socrates, karpathy, taleb, rams, aristotle, kahneman, munger, feynman, lao-tzu, …) invoked by an agent. Each persona produces its own claim or annotation.
Critic insight-kit
A tier of claim emitted by a critic agent that falsifies, partial-validates, or accepts a parent derived claim. Requires at least one supports or refutes edge (Layer-A rule).
DAG cross
Directed acyclic graph. In Hamilton: nodes = functions, edges = parameter-name matches. In insight-kit: claim ancestry via input_claims.
DataSaver / DataLoader hamilton
Abstract I/O adapter. Subclass to ride @save_to.<format> / @load_from.<format>. The integration plan introduces a RunScopedParquetSaver that resolves paths into .insight-kit/runs/<id>/output/.
Driver hamilton
Builder-pattern entry point. driver.Builder().with_modules(...).with_adapters(...).with_executor(...).build() produces a Driver; .execute(...) runs it.
DuckDB evidence
Embedded analytic database. Parquet snapshots in .insight-kit/runs/.../output/ are mounted into a shared DuckDB warehouse via scripts/build_duckdb_views.py, which Evidence.dev queries.
Evidence.dev evidence
SQL-first BI framework. Pages are .md with embedded SQL + chart components. The current seam to insight-kit is filesystem-based via DuckDB views and a local npm dep @insight-kit/viz-evidence.
Executor hamilton
Swappable backend that runs the DAG: SynchronousLocalTaskExecutor, MultiProcessingExecutor, RayExecutor, DaskExecutor, SparkExecutor.
@extract_columns hamilton
Unpack a multi-column DataFrame into one node per column, so downstream nodes can depend on a specific column.
final_vars hamilton
The list of node names you ask the Driver to materialise. Hamilton walks ancestors and runs only what's needed.
Fingerprint hamilton
Hash of (code body + upstream inputs + relevant config) used by HamiltonCacheAdapter as the cache key.
GraphValidator hamilton
Adapter interface that runs at Driver build time over the entire FunctionGraph. In the deep-refactor option, insight-kit's Layer-A claim-ID regex, namespace, and critic-edge rules become a InsightKitGraphValidator that walks every node's tags and rejects malformed claim ids before any compute runs.
NodeValidator hamilton
Per-node validator that fires after a node executes — a lighter cousin of @check_output. Used in the deep refactor to check that @tag(claim_id=…) nodes return a payload compatible with the declared claim_tier.
ResultBuilder hamilton
Adapter that shapes the output of Driver.execute(). In the deep refactor, the InsightKitResultBuilder walks the executed nodes, harvests @tag metadata, and serializes the run as manifest.json + claims.jsonl — replacing the per-Run context manager's write logic.
Goal insight-kit
An analytical hypothesis declared in .insight-kit/goals/catalog.yaml. Fields: statement, criteria, data_scope, horizon, owner, status, output_claims. Lifecycle: open → closed via open_queue.jsonl / closed.jsonl.
h_* plugin hamilton
Optional Hamilton plugin: h_pandas, h_polars, h_dlt, h_ray, h_dask, h_spark, h_openlineage, h_mlflow, h_diskcache, h_mcp, h_narwhals.
Hook hamilton
A method on an Adapter that fires at a lifecycle stage: pre_graph_execute, pre_node_execute, post_node_execute, post_graph_execute, etc. Multiple adapters' hooks stack.
input_claims insight-kit
List of upstream claim IDs cited by a claim. Source of cross-run lineage. Layer A validates that every referenced claim exists in this run or any prior run.
InputRecord insight-kit
Provenance record for an ingested input: path, sha256, bytes, rows, content_type, source_id, default_caveats. Filed via Run.ingest_*.
Kit root insight-kit
The directory holding .insight-kit/, located by walking upward from CWD via find_kit_root(). ik bootstrap creates it.
Layer A / B / C insight-kit
Three validation tiers. A: real-time per-Run (claim-ID format, namespace, referential integrity, critic-edge rule, external-caveat rule). B: post-Run global uniqueness scan. C: cross-project via ik validate.
Layer 1–6 (preflight) insight-kit
Different axis. ik preflight runs six checks: schema validity, run integrity, claim coverage, evidence density, evidence viz, skill availability.
Lifecycle hook hamilton
See Hook. The integration seam between Hamilton's compute graph and insight-kit's provenance layer.
Lineage cross
Two senses: compute lineage (Hamilton DAG topology, queryable via dr.what_is_upstream_of); claim lineage (insight-kit's input_claims / supports / refutes / supersedes edges).
manifest.json insight-kit
Per-Run summary written on Run.__exit__. Contains metadata, all InputRecord / OutputRecord / ApiCall, code SHA, git state, runtime telemetry.
Materialize hamilton
Driver.materialize(dependencies=[...]) fires @save_to.<fmt> nodes — declarative I/O as DAG nodes, not side effects.
Namespace insight-kit
The 2–5 letter prefix on every Claim ID for a project. DOCK, NMK, etc. Layer-A rule enforces all emitted claims match the configured namespace.
Node hamilton
A function in a Hamilton module. Name = function name. Inputs = typed parameters. Output type = return annotation. Tags = @tag.
OpenLineage cross
Open spec for data lineage events. Hamilton can emit via h_openlineage. Prior memory chose OpenLineage over alternatives; deferred until a real catalog is deployed.
OutputRecord insight-kit
Provenance record for an emitted artifact: path, sha256, layer (metric/critique/viz/raw), rows, schema, duckdb_view. Filed by Run.emit_* or the Hamilton hook.
@parameterize hamilton
Decorator that expands one function into N nodes by sweeping a parameter. The natural shape for the council pattern: one function, five persona lenses.
Parquet cross
Columnar storage format. The canonical artifact unit in .insight-kit/runs/.../output/<layer>/*.parquet. Each parquet has a sibling .sha and .schema.json.
Provenance cross
The story of where an artifact or claim came from: which inputs, what code, which run, which goal. insight-kit's central concern.
Run insight-kit
The context manager with Run(topic, agent) as run: .... On enter, opens a timestamped run directory under .insight-kit/runs/. On exit, writes the manifest, claims, env.lock, checksums.
run_id cross
Hamilton: uuid passed to every hook. insight-kit: <date>_<time>_<agent>_<topic-slug> dir name. The integration stores Hamilton's uuid as hamilton_run_id in the manifest.
Schema drift insight-kit
Skill schema-drift/ compares emitted output schema to the registered schema for a claim; flags additions, removals, type changes across runs.
script.py insight-kit
The user's executable for a Run, copied verbatim into the run directory for reproducibility. The integration plan replaces per-run procedural scripts with one declarative Hamilton module per topic.
Shim insight-kit
Back-compat wrapper. Recent commits (5f7ab73) add shims for Run.claim(id=) and Run.emit() to keep older call sites working as the API tightens.
@subdag hamilton
Embed a sub-graph as a single node in a parent graph. Pairs with @parameterize for "critic-of-claim-X across N angles" in one declaration.
supersedes insight-kit
Edge from a new claim to an older one it replaces. Lets a claim be re-emitted with the same logical identity but updated value. Layer-B rule allows duplicate claim IDs only when a supersedes chain exists.
@tag hamilton
Attach KV metadata to a node: @tag(emit="metric", claim_tier="derived", claim_id="DOCK-D-001", confidence="high"). InsightKitHook reads these in post_node_execute to dispatch into Run.emit_* / Run.claim().
Topic insight-kit
Short slug identifying a Run's subject (e.g. brevo-attribution, g2-levers). Used in the run-dir name.
viz / Evidence seam evidence
The path from viz-tier claims to Evidence.dev pages. Today: parquet → DuckDB view → SQL source → hand-written .md page that imports @insight-kit/viz-evidence components.
