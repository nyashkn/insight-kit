Closing the text + charts hallucination loop

Real consumer-repo bugs: health.md showed +115,070 KES when the truth was −11,079 KES — sign flipped. g4_retargeting_leak.md rendered 5160% for what should have been 51.6%. monthly_pl displayed MER 9.26x built on partial-month spend. Each cost a revision sprint. This page proposes a closed loop: <ClaimNum> · ProvenanceRail · L6 preflight · post-render diff.

§2Council · 6 voices

Feynman · first principles

The number +115,070 entered the system as a string literal. Once a literal, no downstream check distinguishes correct from incorrect. Fix: eliminate the channel. Numbers never exist as string literals in source prose. A claim ref is a pointer resolved at render time against ground truth.

Kahneman · cognitive bypass

Writer pastes a number it didn't compute because contextual plausibility wins: number from prompt examples + prior runs in context window → System 1 pattern-match. Checklists fail under load. Need System 2 guard at machine speed: <ClaimNum> that refuses to render if claim missing.

Karpathy · empirical eval

Regression test = numeric diff post-build. Extract every numeric token from rendered HTML (outside <code>), join against claims.jsonl, assert 100% provenance coverage. 5160% would have flagged instantly — no claim has that field. Cheap, fast, addresses the failure mode.

Taleb · tail risk

Sign flips are catastrophic (health.md +115k → −11k inverts the decision). Prioritize defense on sign-bearing numbers (net, delta, comparison) > denominators inflating ratios (partial-month MER) > absolute magnitudes. Critic agent catches wrong-baseline claims at the source — DOCK-C-007 vs D-005.

Rams · simplicity

Invisible when correct. Author writes <ClaimNum claim_id="X" field="y"/>, preview shows formatted number, no lookup. Friction appears only at build-fail (claim missing). The g4 double-fix collapses to one fix: fmt lives on the component, value lives in claim.

Sun Tzu · adversarial

LLM finds path of least resistance. If <ClaimNum fallback="2.36x"/> is allowed, fallback becomes new hardcode vector — strip the attribute. LLM will write "approximately 2.36x" in prose near a tag → preflight must reject ALL bare numeric literals in prose, not just mismatches.

Synth · verdict

Two-layer enforcement, both machine-checked, both blocking on board-facing pages: (a) Numbers originate ONLY from (run_id, claim_id, field) triples in claims.jsonl; rendered via <ClaimNum> component that hard-errors on missing claim. (b) L6 preflight regex over reports/pages/**/*.md rejects ANY bare numeric literal in narrative prose (outside fences / outside <ClaimNum>). Belt-and-suspenders: post-render diff scans HTML output, asserts 100% of numeric tokens trace to claims. Critic agent surfaces challenges as critique field on claim → ProvenanceRail flags non-ignorably.

§3Six-layer mechanism — technical spec

L1

Claim is the only source of numbers

claims.jsonl · per run

Every numeric fact emitted as (claim_id, field, value, fmt_hint, run_id, coverage_warnings[]). Multiple fields per claim OK. coverage_warnings e.g. partial_month, n_lt_30, baseline_cherry_picked surface upstream caveats.

L2

<ClaimNum> component · no fallback

renderer surface

Single tag binds claim_id + field. Resolves at build. No fallback= attribute (Sun Tzu rule). Wraps in <span data-prov="run_id:claim_id:field"> for rail click-through. Missing claim = hard build error.

// in any .md page
<ClaimNum claim_id="MD-D-005" field="net_cash_kes"/>
// renders: -11,079 KES · with provenance attr

// FORBIDDEN — won't typecheck
<ClaimNum claim_id="MD-D-005" field="net_cash_kes" fallback="+115,070"/>

// fmt override allowed — uses field's fmt by default
<ClaimNum claim_id="MD-D-005" field="net_cash_kes" fmt="kes_short"/>

Solves: health.md sign flip (literal can't exist) · g4 5160% (fmt comes from claim spec, not page tag).

L3

renderer · viz layer

V-tier claims store chart spec JSON. <ClaimChart claim_id="V-001"/> resolves type / x / y / encoding / fmt from claim. Axis fmt + value fmt come from claim, not page. The g4 double-fix (Column fmt=pct1 AND BarChart yFmt=pct1) collapses — fix the V-claim once.

L4

L6 preflight · narrative literal lint

pre-build · CI blocking

Regex over reports/pages/**/*.md. Rejects bare numeric literals in narrative prose (lines outside fenced code blocks, outside <ClaimNum>/<ClaimChart>/{{ claim:… }} markers). Pattern: [\d][\d,\.]*[%xX]?. Year tokens (2024-2026) allow-listed.

# scripts/ik_preflight_L6_narrative_literals.py
import re, sys, pathlib

LITERAL = re.compile(r"(?<![\w.])([+\-]?\d[\d,]*(?:\.\d+)?[%xX]?)(?![\w])")
ALLOW  = {"2024", "2025", "2026"}

def scan(path):
    src = path.read_text().splitlines()
    in_fence = False; fails = []
    for i, line in enumerate(src, 1):
        if line.lstrip().startswith("```"): in_fence = not in_fence; continue
        if in_fence: continue
        if "<ClaimNum" in line or "<ClaimChart" in line: continue
        for m in LITERAL.finditer(line):
            if m.group(1) in ALLOW: continue
            fails.append((path, i, m.group(1), line.strip()))
    return fails

fails = [f for p in pathlib.Path("reports/pages").rglob("*.md") for f in scan(p)]
if fails:
    for p, ln, lit, ctx in fails:
        print(f"L6 FAIL {p}:{ln}  literal={lit!r}  near: {ctx[:80]}")
    sys.exit(2)

Catches: the four hardcoded KPIs on health.md line 9 before build starts.

L5

Post-render diff · HTML token audit

post-build · CI blocking

Belt-and-suspenders. After Evidence builds, parse rendered HTML, extract every numeric token outside <code>/<pre>/data-prov-wrapped spans, join against claims.jsonl. Tolerance ±0.5% for rounding. Anything unmatched → fail. This is what catches a claim that resolves to a stale value.

# scripts/ik_postrender_numeric_audit.py
from bs4 import BeautifulSoup
import json, re, pathlib, sys

claims = json.loads(pathlib.Path("claims.jsonl").read_text())
known  = {(c["claim_id"], f, v["value"])
          for c in claims for f, v in c.get("fields", {}).items()}

TOKEN = re.compile(r"[+\-]?\d[\d,]*(?:\.\d+)?")
def walk(html):
    soup = BeautifulSoup(html, "lxml")
    for tag in soup("code"): tag.extract()       # skip code blocks
    for tag in soup("pre"):  tag.extract()
    for el in soup.find_all(attrs={"data-prov": True}):
        el.extract()                                  # trusted (came from claim)
    return TOKEN.findall(soup.get_text())

orphans = [t for p in pathlib.Path("reports/build").rglob("*.html")
              for t in walk(p.read_text())
              if not any(close(float(t.replace(",","")), v, 0.005)
                     for _, _, v in known)]
if orphans: print(orphans); sys.exit(2)

Catches: g4's 5160% rendered token (no claim has 5160) · stale claim ref that resolves to old value · narrative drift around <ClaimNum> tags.

§4The closed loop · text + charts

Two failure loops, both red-dashed: L6 fail forces narrative rewrite (cheap, local). L5 fail forces upstream claim rerun (expensive, traces back to data). The latter is what catches the monthly_pl partial-month case — claim wrong → page renders wrong number → diff shows orphan → re-extract w/ proper date window → re-emit claim → re-render.

§6.5Migration: existing C-claims → inline critiques

Today, critic challenges float as independent sibling entries in their own run's claims.jsonl — DOCK-C-007 lives in the critic-data-quality_critic-pass run, far from DOCK-D-005 in the analyst run it challenges. The provenance-loop spec (§3 L6) proposes a single canonical home: a critiques[] array embedded directly on the challenged D-claim. Moving the challenge inline makes it non-ignorable: any reader, tool, or ProvenanceRail rendering D-005 sees the open challenge without cross-referencing a second run, and downstream code that reads by claim_id gets the full picture from one record.

The migration rewrites claims.jsonl lines in-place. A .jsonl.bak sibling is created before the first write to each file. Do not delete the .bak files until the migrated state has been reviewed and committed. If anything looks wrong after a real run, restore with: cp .insight-kit/runs/<run>/claims.jsonl.bak .insight-kit/runs/<run>/claims.jsonl Always run --dry-run first, review every printed line, then proceed. Treat the git diff after migration as the definitive audit record.

What stays unchanged

The original C-claim entries in their respective claims.jsonl files are preserved for audit — the script only sets "superseded_by_inline": true on them so tooling can distinguish active from archived critic claims. The D-claim's claim_id is untouched: any downstream code, ProvenanceRail lookup, or <ClaimNum claim_id="DOCK-D-005"> reference continues to resolve correctly. The only structural addition is the critiques[] array on the D-claim — all existing fields are preserved verbatim.

Verdict · 2026-05-14

Two layers, six gates, zero literal numbers in narrative prose.

  1. Single source: every number originates from (run_id, claim_id, field). Migrate claim schema to fields: dict[str, {value, fmt}].
  2. One component, no fallback: <ClaimNum> + <ClaimChart>. Strip any escape hatch attribute — Sun Tzu rule.
  3. L6 preflight: regex over reports/pages/**/*.md rejects bare numeric literals in prose. Pre-build, blocking, ~½ day to ship.
  4. L5 post-render diff: extract HTML tokens, join against claims, fail on orphans. Catches stale-claim case.
  5. Critic critiques on the claim: non-ignorable rail flag. Catches cherry-picked baselines at the source.
  6. Graded rollout: blocking on audience: board, warning on internal, off on draft. Promotion tightens gates.

Glossary

<ClaimNum/>
Renderer component. claim_id + field → numeric render, fmt from claim. No fallback= attribute. Missing claim = hard build error.
<ClaimChart/>
Renderer component. V-tier claim → chart spec (type/x/y/axes/fmt). One claim, one chart — no per-page format duplication.
ProvenanceRail
Right-rail or footer element that lists every (run_id, claim_id, field) rendered on the page + active critiques. Click-through to source run.
L6 preflight
Pre-build lint. Regex rejects bare numeric literals in narrative prose outside fences / outside ClaimNum tags. Exit 2 on fail. Blocking on audience: board.
L5 post-render diff
Post-build audit. Extract HTML numeric tokens, join against claims.jsonl ±0.5%, fail on orphans. Catches stale-claim renders.
critiques[] (on claim)
Array of critic-emitted records on the challenged claim. Severity + statement + resolution. Rail renders ⚠ — non-ignorable but non-blocking.
coverage_warnings
Claim-level flags surfacing upstream caveats: partial_month, n_lt_30, baseline_cherry_picked. Render in rail next to value.
data-prov attr
HTML span attribute wrapping every ClaimNum render: data-prov="run_id:claim_id:field". Used by L5 diff to skip trusted tokens, used by rail for click-through.
audience: frontmatter
Page-level tag: board · founder · internal · draft. Drives gate strictness — board pages fail on any L6/L5 hit; draft pages skip both.
fmt spec
Format hint on claim field: kes · kes_signed · pct1 · num1 · xFactor. Drives both numeric rendering AND chart axis labels.
